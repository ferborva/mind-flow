5. **Dashboard and public experience.** Rebuild existing interfaces without
   restyling. Check fiscal-year dates, source ceilings, distinct NSW/Australia
   results, zero-placeholder count and historical correction identities. Test
   whether a reader mistakes a proxy, favorable trend or coverage for agency.
6. **Freeze, CI and repository integrity.** Reproduce retained inputs and
   declared commands. Verify LFS content against pointer hash and size, output
   byte parity, exact untracked-file checking and rejection of failed reproduction.
   The receipt verifier checks consistency; it does not rerun commands or prove
   output authenticity. Independently execute the checks.
7. **Human and affected-party review.** No human consultation occurred this
   round. The existing protocols remain proposals. Actual recruitment needs
   separate approval. Assess what remains necessary for comprehension,
   accessibility, refusal, challenge and meaningful affected-party participation.
8. **Measurement validity.** Use public-finance, rural GP, Medicare-statistics,
   disability and low-income perspectives without pretending those people were
   consulted. Challenge denominators, nonattendance, survey exclusions,
   historical freshness, ecological joins, post hoc favorable selection, rule
   eligibility versus use and proxy validity. Do not count repeated projections
   as independent measurements or change a gate's wording to make it pass.

## Reproduction and reporting

Use Node 22, `npm ci`, `npm test`, and every command in the Round 08 freeze
policy. Fetch the LFS archive first. `npm test` regenerates ignored interfaces;
`node meta/build-artifacts.mjs --check` requires regular output files and verifies
their deterministic byte parity. The freeze records executable identities,
command outputs and complete tracked-tree inventory. The execution environment
is not a security sandbox for untrusted code.

Report findings with severity, exact target hash and path, expected versus
observed behavior, a bounded defensive check, and the narrowest justified
repair. Separate mechanical integrity, measurement validity, public meaning and
authority. A red result is useful; an unsupported green result is not.

Keep these deferrals open: freeze hash-domain separation for schema 2.0,
review date 2026-09-16; coherent fabricated command receipts because verification
does not execute them; and repository weight from earlier Git history. LFS
reduces newly committed object weight, not the old history already published.

Return the candidate if a reported measurement cannot reproduce, chronology
permits retrospective forecast changes, a score leaks before eligibility, an
unsupported personal claim appears, or current access/authority is inferred
from a contextual indicator. Do not turn a local technical pass into approval
to publish or act.
