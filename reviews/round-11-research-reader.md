## ⚙️ What is pinned and reproduced

The reader builder checks the byte hashes of the review transcript, adoption manifest and corrected proposal, then reproduces the proposal from its original source pins. It resolves each selected existing reader to the exact original artefact and JSON Pointer. The retained original fragment must still contain the expected old binding.

The new JSON reader, summary and static page are deterministic. Rendering validates the exact edition first; a changed binding, omitted reader, invented evidence, rewritten old value, false human approval or modified source hash fails. This is content integrity, not authentication of the person or institution behind a claim.

The old proposal preview API and its refusal rules are unchanged. New counts live in a separately named summary so the station cannot reasonably label three metadata adoptions as three completed construct corrections.
